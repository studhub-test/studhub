# StudHub — исправление поля уникального юзернейма

Я проверил архив твоего проекта: JavaScript уже пытается прочитать `authUsername`, но в `index.html` самого поля не было. Поэтому регистрация не могла нормально работать. В этом архиве поле добавлено в актуальный `index.html` и сохранены согласованные файлы логики юзернейма.

## Что делать

1. **Сначала сделай резервную копию** текущего репозитория или скачанного ZIP.
2. На GitHub открой `index.html` → карандаш **Edit this file**. Самый безопасный вариант — заменить весь `index.html` содержимым `index.html` из этого архива. Это именно файл из присланного тобой архива с добавленным полем, а не старый шаблон.
3. Проверь, что на GitHub уже обновлены одноимённые файлы из этого архива: `js/auth.js`, `js/backend.js`, `js/profile.js`, `js/i18n.js`. В `js/auth.js` регистрация должна передавать `username: $('authUsername').value`; в `js/backend.js` `backendRegister` должен передавать `username` в metadata Supabase.
4. Если миграцию `supabase/username-migration.sql` уже запускал и она завершилась без ошибок, повторно её запускать не нужно. Если не запускал — выполни её в Supabase → SQL Editor.
5. В `sw.js` увеличь `VERSION`, например с `studhub-v6` на `studhub-v7`, чтобы браузер не использовал старые файлы.
6. Дождись публикации GitHub Pages, затем открой сайт с жёстким обновлением `Ctrl + Shift + R`. На телефоне закрой старую вкладку сайта и открой заново.

## Проверка

- Нажми **Регистрация** — под полем имени должно появиться поле «Юзернейм».
- Введи 3–20 символов: латинские буквы, цифры, точка или подчёркивание.
- Юзернеймы должны быть уникальными без учёта регистра.

Важно: аккаунты в демо-режиме хранятся только в браузере. Для настоящей общей системы аккаунтов в проекте должен быть настроен Supabase (`js/config.js`) и выполнена SQL-миграция.
