# StudHub — уникальные юзернеймы

Этот архив — **патч**, а не полный сайт. Не заменяй им весь проект и не перезаписывай `index.html` целиком: так можно потерять последние изменения интерфейса обсуждений.

## Что меняется
- при регистрации появляется поле юзернейма;
- формат: 3–20 символов, `a-z`, `0-9`, точка и `_`; регистр не учитывается;
- Supabase проверяет уникальность на уровне PostgreSQL;
- текущим аккаунтам миграция назначает юзернеймы на основе email и добавляет суффикс при совпадениях;
- юзернейм можно изменить в редактировании профиля, проверка уникальности действует и там.

## Шаг 1. Сначала база данных
1. Открой Supabase → **SQL Editor** → **New query**.
2. Открой `supabase/username-migration.sql` из архива, скопируй весь текст в редактор Supabase и нажми **Run**.
3. Убедись, что запрос завершился без ошибок. Миграция не удаляет профили и кошельки.

## Шаг 2. Обнови JavaScript на GitHub
Замени содержимое этих файлов в репозитории содержимым одноимённых файлов из архива:
- `js/auth.js`
- `js/backend.js`
- `js/profile.js`
- `js/i18n.js`

## Шаг 3. Добавь поле в регистрацию
1. Открой текущий `index.html` в GitHub.
2. Найди поле `id="authName"`.
3. Сразу после блока с `authName` и перед полем Email вставь содержимое `registration-field-snippet.html`.
4. Сохрани изменения. Не загружай `index.html` из старого архива поверх актуального файла.

## Шаг 4. Обнови кеш Service Worker
В текущем `sw.js` увеличь версию кеша на единицу. Если сейчас `studhub-v5`, поставь `studhub-v6`:
```js
const VERSION = 'studhub-v6';
```
Не заменяй весь `sw.js` из старого архива — там может быть старая версия.

## Шаг 5. Проверка
После публикации открой сайт через `Ctrl + Shift + R`:
1. В форме регистрации появилось поле «Юзернейм».
2. Зарегистрируй тестовый аккаунт с новым юзернеймом.
3. Попробуй зарегистрировать второй тестовый аккаунт с тем же юзернеймом — база не должна разрешить дубликат.
4. В редактировании профиля попробуй поставить уже занятое имя — появится сообщение «Этот юзернейм уже занят».

Примечание: если в Supabase включено подтверждение email, регистрация может попросить подтвердить почту прежде, чем пустить в аккаунт. Это штатное поведение.
